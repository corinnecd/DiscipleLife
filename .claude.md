# DiscipleLife - Application de Suivi de Disciplat

## 📋 Contexte du Projet

**DiscipleLife** est une application web de gestion et suivi de disciples pour l'église Impact Centre Chrétien (ICC) au Gabon.

### Objectif Principal
Accompagner la croissance spirituelle et organisationnelle de l'église à travers:
- Suivi personnalisé de chaque disciple
- Gestion des familles spirituelles (objectif: 70 disciples/famille)
- Reporting des activités et KPI
- Arbre généalogique spirituel (filiation disciple → mentor → superviseur → pasteur)

### Stack Technique
- **Frontend**: React 18.2 + Vite 4.5 + Tailwind CSS 3.3.5
- **Backend**: Supabase (PostgreSQL + Auth + RLS)
- **UI**: Radix UI (27 composants accessibles)
- **Forms**: React Hook Form + Zod
- **Charts**: Recharts
- **State**: React Context API (Auth, Role, Theme)

---

## 🏗️ Architecture Hiérarchique

```
super_admin / admin / pasteur (Pasteur/Évêque)
    ↓ Gère plusieurs superviseurs
    └── PasteurDashboard

superviseur (Superviseur)
    ↓ Gère 1-N familles (objectif 70 disciples/famille)
    └── SuperviseurDashboard

mentor (Mentor/Berger)
    ↓ Gère N disciples personnels
    └── MentorDashboard

disciple (Disciple)
    ↓ Accès ressources, parcours
    └── DiscipleDashboard
```

### Familles Spirituelles
- **26 familles** configurées
- Chaque famille a un **superviseur assigné**
- Objectif: **70 disciples par famille**
- Pasteurs de tutelle: 4 pasteurs gèrent les familles

## 🔒 Sécurité & RLS Policies

### Row Level Security (RLS)
Toutes les tables Supabase doivent avoir des **RLS policies** strictes:

```sql
-- Exemple: Table profils
CREATE POLICY "Users can view profiles in their hierarchy"
ON profils FOR SELECT
USING (
  auth.uid() = id OR
  auth.uid() IN (SELECT mentor_id FROM profils WHERE id = profils.id)
);
```

### Principes de Sécurité
1. **Jamais de données sensibles** côté client
2. **Validation** côté serveur (Zod + RLS + Triggers)
3. **Chiffrement** pour données confidentielles (signalements d'abus)
4. **Audit log** pour actions critiques
